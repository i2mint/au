au.base#

Asynchronous computation framework with pluggable backends.

This module provides a decorator-based approach to transform synchronous functions into asynchronous ones that return immediately with a handle to check status and retrieve results later.

Architecture Overview:#

  1. Storage abstraction (ComputationStore): Implements MutableMapping interface

  2. Execution abstraction (ComputationBackend): Handles computation launching

  3. Result handling (ComputationHandle): Clean API for status/result retrieval

  4. Middleware system: For cross-cutting concerns like logging and metrics

  5. Cleanup mechanisms: Automatic expiration of old results

Usage Patterns:#

Simple file-based async:

>>> @async_compute()
... def my_function(x):
...     return x * 2

Custom configuration (example setup):

>>> import tempfile
>>> with tempfile.TemporaryDirectory() as tmpdir:
...     store = FileSystemStore(tmpdir, ttl_seconds=3600)
...     backend = ProcessBackend(store, middleware=[LoggingMiddleware(), MetricsMiddleware()])
...     @async_compute(backend=backend, store=store)
...     def api_computation(data):
...         return data * 2
...     # Function is ready to use
...     True

Bases: Exception

Raised by ComputationHandle.get_result() when a computation was cancelled.

This lets callers distinguish a deliberate user cancellation (a first-class ComputationStatus.CANCELLED) from a genuine computation failure (ComputationStatus.FAILED) without string-sniffing the error message.

cancel(*, reason='Computation cancelled')[source]#

Attempt to cancel the computation.

Writes a first-class ComputationStatus.CANCELLED result (not a FAILED one), so callers can tell a deliberate cancellation apart from a genuine failure via get_status() without inspecting error text.

Parameters:

reason (str) – Human-readable reason stored on the result’s terminal_reason (surfaced by ComputationCancelledError from get_result()).

Return type:

bool

Returns:

True if cancelled, False if already in a terminal state.

Note

A thread, or a pool task that is already running, cannot be stopped; the au workers keep CANCELLED final anyway by not writing their outcome over it. after_compute then receives the CANCELLED result. A worker finishing in the instant between its check and its write can still overwrite it (no compare-and-set).

au.base.async_compute(backend=None, store=None, *, base_path='/tmp/computations', ttl_seconds=3600, serialization=SerializationFormat.JSON, middleware=None)[source]#

Decorator to make functions asynchronous with status tracking.

Parameters:

  • backend (ComputationBackend | Callable | None) – Backend to execute computations (default: the module’s _default_backend, else ProcessBackend). @async_compute may also be used bare, without parentheses.

  • store (ComputationStore | None) – Store for results (default: FileSystemStore)

  • base_path (str) – Path for FileSystemStore if no store provided

  • ttl_seconds (int | None) – Time-to-live for results (default: 1 hour)

  • serialization (SerializationFormat) – Format for storing results

  • middleware (list[Middleware] | None) – List of middleware components

Return type:

Callable

The default backend runs each call with a copy of its middleware, in a child process: a plain MetricsMiddleware counts there, not in the instance you hold. Use SharedMetricsMiddleware to count across processes.

Example

>>> metrics = SharedMetricsMiddleware()
>>> @async_compute(
...     ttl_seconds=7200,
...     middleware=[LoggingMiddleware(), metrics]
... )
... def slow_computation(x: int) -> int:
...     return x * x
>>> handle = slow_computation(5)  # Returns immediately
>>> result = handle.get_result(timeout=10)

A failing hook is logged. A BaseException from one is re-raised once all have run, so one hook cannot leave another middleware’s key registered.

Return type:

au.base.compute_and_record(func, args, kwargs, *, key, store, middleware)[source]#

Run func, record its outcome under key, and drive the middleware.

The body the thread and queue workers run, and ProcessBackend’s child. Once before_compute has run, exactly one of after_compute / on_error runs too, whatever fails (a hook, the RUNNING write, the COMPLETED write, the FAILED write), so middleware that registers a key in one can always release it in the other. A BaseException (asyncio.CancelledError, SystemExit, even sys.exit(0)) is recorded as FAILED like any error, then re-raised (i2mint/au#12). A cancellation already recorded is final.

Return type:

None
