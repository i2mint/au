exception au.ComputationCancelledError[source]#

Bases: Exception

Raised by ComputationHandle.get_result() when a computation was cancelled.

This lets callers distinguish a deliberate user cancellation (a first-class ComputationStatus.CANCELLED) from a genuine computation failure (ComputationStatus.FAILED) without string-sniffing the error message.

cancel(*, reason='Computation cancelled')[source]#

Attempt to cancel the computation.

Writes a first-class ComputationStatus.CANCELLED result (not a FAILED one), so callers can tell a deliberate cancellation apart from a genuine failure via get_status() without inspecting error text.

Parameters:

reason (str) – Human-readable reason stored on the result’s terminal_reason (surfaced by ComputationCancelledError from get_result()).

Return type:

bool

Returns:

True if cancelled, False if already in a terminal state.

Note

A thread, or a pool task that is already running, cannot be stopped; the au workers keep CANCELLED final anyway by not writing their outcome over it. after_compute then receives the CANCELLED result. A worker finishing in the instant between its check and its write can still overwrite it (no compare-and-set).

class au.MetricsMiddleware[source]#

Bases: Middleware

Middleware for collecting computation metrics, in the copy that runs the computation.

Every backend but ThreadBackend runs a copy (a child process’s, or one a queue worker unpickled), so there the instance you hold counts nothing. Use SharedMetricsMiddleware with ProcessBackend to count across processes.

>>> metrics = MetricsMiddleware()
>>> metrics.get_stats()
{'total': 0, 'completed': 0, 'failed': 0, 'avg_duration': 0.0}

Callable

...     ttl_seconds=7200,

au.submit_task(func, *args, key=None, backend=None, store=None, retry_policy=None, **kwargs)[source]#

Submit a task for async execution without decorator.

Parameters:

  • func (Callable) – Function to execute

  • *args – Positional arguments for function

  • key (Optional[str]) – Optional caller-supplied idempotency key. When omitted, a fresh key is minted per call. When supplied and a live (in-flight) computation already exists for that key, the existing task is returned instead of launching a duplicate — so a resubmit runs the work at most once while it is in flight. A terminal (completed/failed/cancelled) or expired key re-runs.

  • backend (Optional[ComputationBackend]) – Optional backend (uses default if not provided)

  • store (Optional[ComputationStore]) – Optional store (uses default if not provided)

  • retry_policy (Optional[RetryPolicy]) – Optional retry policy

  • **kwargs – Keyword arguments for function

Return type:

str

Returns:

Task ID (key) for retrieving results

Example

>>> task_id = submit_task(my_func, 5, multiplier=2)
>>> result = get_result(task_id, timeout=10)

>>> # Idempotent submission: resubmitting the same key while in flight
>>> # returns the running task rather than launching a duplicate.
>>> task_id = submit_task(my_func, 5, key="my-job")
>>> same_id = submit_task(my_func, 5, key="my-job")
