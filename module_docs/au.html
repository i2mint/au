exception au.ComputationCancelledError[source]

Raised by ComputationHandle.get_result() when a computation was cancelled.

This lets callers distinguish a deliberate user cancellation (a first-class ComputationStatus.CANCELLED) from a genuine computation failure (ComputationStatus.FAILED) without string-sniffing the error message.

au.submit_task(func: Callable, *args, key: str | None = None, backend: ComputationBackend | None = None, store: ComputationStore | None = None, retry_policy: RetryPolicy | None = None, **kwargs) → str[source]

  • *args – Positional arguments for function

  • key – Optional caller-supplied idempotency key. When omitted, a fresh key is minted per call. When supplied and a live (in-flight) computation already exists for that key, the existing task is returned instead of launching a duplicate — so a resubmit runs the work at most once while it is in flight. >>> same_id = submit_task(my_func, 5, key="my-job")
